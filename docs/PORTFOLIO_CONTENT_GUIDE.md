# 포트폴리오 운영 가이드 (실무자용)

개발 지식이 없어도 읽을 수 있게 정리했습니다. 실제 파일 수정은 Claude나 개발자가 하고,
여러분이 준비할 것은 **사진, 간단한 설명, 공개 가능 여부 확인**입니다.

---

## 1. 신규 포트폴리오 추가

가장 쉬운 방법은 `docs/PORTFOLIO_INTAKE.md`의 등록 양식을 채워 Claude 프로젝트에 보내는 것입니다. 짧게 이렇게만 보내도 됩니다.

> 새 포트폴리오 등록해줘.
> 프로젝트명: OOO
> 설명: OOO 기업의 내부 업무를 통합 관리하는 ERP 시스템. 배차, 직원 관리, 급여, 결재 기능이 있음.
> 이미지: 첨부한 화면 8장.
> FITY처럼 포트폴리오 만들고 홈페이지에 반영해줘. PDF도 만들어줘.

Claude가 정해진 틀대로 문구(한·영·일), 화면 배치, PDF까지 만들고 확인이 꼭 필요한 것만 묻습니다.

직접 하는 경우(개발자):
1. `npm run portfolio:new -- abc-erp` → `content/portfolio/abc-erp/` 생성 (상태: 초안)
2. 사진을 `content/portfolio/abc-erp/images/`에 넣기
3. `project.json`의 문구·이미지 목록·블록 채우기 (FITY 파일이 완성 예시)
4. `npm run portfolio:check` → 오류 0건 확인
5. 공개 승인 후 `status`를 `approved`로 바꾸고 배포

새 페이지나 새 디자인을 만들 필요가 없습니다. 데이터만 넣으면 목록·상세·PDF가 자동으로 만들어집니다.

## 2. 사진 준비

**공개해도 되는 화면인지 먼저 확인하세요.** 링크를 빼는 것만으로 정보가 보호되지 않습니다.
- 실제 고객 이름·연락처·주소·주문 내역·금액 같은 **운영 데이터가 보이면 안 됩니다.** 테스트 계정·더미 데이터 화면으로 다시 캡처하거나 가려 주세요.
- 실사용자 얼굴 사진은 공개 동의가 있는 경우만. 없으면 흐리게 처리하거나 샘플 이미지로 교체.
- 화면 안의 서버 주소, 관리자 URL, 내부 메뉴명 중 비공개인 것도 확인.
- **거래처(고객사)는 공개 금지.** 이름·로고·상호·서비스명이 글과 화면 어디에도 나오면 안 됩니다. 업종·성격으로 바꿔 쓰고, 화면 속 이름·로고는 가립니다. 거래처 이름은 `content/portfolio/_clients.txt`에 한 줄씩 넣어 두면 검사가 막아 줍니다.

**어떤 화면을 고를까**
- 대표 화면 3장: 가장 완성도 높은 앱 화면 (목록 카드·표지에 사용)
- 사용자 흐름 화면: 처음부터 끝까지 순서대로 4~6장
- 웹·관리자 화면: 업무가 잘 보이는 대표 화면 1~3장
- 같은 화면을 두 번 쓰지 않도록 넉넉히 주시면 좋습니다.

## 3. 사진 권장 크기와 비율

| 종류 | 권장 크기 | 비고 |
|---|---|---|
| 모바일 앱 화면 | 1179×2556 (아이폰 원본 캡처) 또는 1080×2340 이상 | 세로 캡처 그대로. 상태바 포함 가능 |
| PC 웹·관리자 화면 | 2880×1800 또는 1920×1200 이상 | 브라우저 주소창 없이 화면 영역만 |
| 태블릿 | 2048×2732 | |
| 사진·그래픽 | 긴 변 1600px 이상 | |

- 형식: **WebP 권장**(PNG·JPG도 가능). 한 장 1.5MB 이하. 크면 검사에서 알려 줍니다.
- 자르지 말고 원본 비율 그대로 주세요. 화면에서도 자르지 않고 틀에 맞춰 보여 줍니다.
- 파일명은 영문 소문자: `app-home.webp`, `admin-orders.webp`

## 4. 서비스 설명 작성

길게 쓸 필요 없습니다. 아래 정도면 충분합니다.
- 무엇을 하는 서비스인지 1~2문장
- 누가 쓰는지 (고객 / 직원 / 관리자 …)
- 주요 기능 몇 가지
- PIUS가 실제로 한 일 (기획, 디자인, 앱 개발, 관리자 개발 …)
- 상태 (개발 중 / 출시 / 운영 중)

지켜야 할 것
- **확인되지 않은 숫자(사용자 수, 매출, 전환율 등)는 넣지 않습니다.** 성과 수치는 출처가 있어야만 등록됩니다.
- 기획만 된 기능을 완성된 것처럼 쓰지 않습니다. 구분이 애매하면 "기획 범위 기준"으로 표시합니다.
- 출시 여부를 모르면 상태를 비워 둡니다.

## 5. 메인 페이지에 나오는 프로젝트

메인 페이지 Process 아래 Portfolio 섹션에는 결과물이 나오지 않고, 공개 프로젝트에서 자동 계산한 숫자(프로젝트·앱·웹·분야)와 기술 스택 띠, "포트폴리오 전체 보기" 버튼만 나옵니다. 프로젝트를 공개하면 숫자가 저절로 바뀝니다.

## 5-1. 수정 · 정렬 · 공개 처리

| 하고 싶은 일 | 바꿀 곳 (`project.json`) |
|---|---|
| 문구 수정 | 해당 항목의 `ko`, `en`, `ja` 세 개를 같이 |
| 사진 교체 | `images/` 파일 교체 (파일명이 같으면 끝) |
| 목록 순서 | `order` — 작을수록 앞 (10, 20, 30… 으로 두면 중간 끼우기 쉬움) |
| 크게 보이기 | `featured: true` (목록에서 한 줄 전체) |
| 잠시 내리기 | `visible: false` |
| 공개 상태 | `status` (아래) |
| PDF에서 빼기 | `includeInPdf: false` |
| 특정 섹션을 PDF에서만 빼기 | 해당 블록에 `"pdf": { "skip": true }` |

**공개 상태**
- `draft` 초안 — 작업 중. 어디에도 안 나옴
- `review` 공개 검토 — Claude 미리보기에서만 보임(표시 없이 화면 그대로). 운영 사이트에는 안 나옴
- `approved` 공개 승인 — 운영 사이트에 나옴. 영어·일본어 번역과 모든 사진이 있어야 승인 가능
- `private` 비공개 — 운영·미리보기 모두 제외. 사진 파일도 공개 폴더로 복사되지 않음

승인되지 않은 프로젝트의 사진과 문구는 운영 빌드 결과물에 **아예 들어가지 않습니다**(화면에서 숨기는 것이 아님).

## 화면 이미지 수량

이미지 10장 고정 규칙은 없습니다. 대표 화면 1장 + 핵심 기능 1~3장을 기본으로, 서비스에 필요한 만큼만 만듭니다. 같은 대시보드의 제목·색만 바꾼 화면으로 수를 늘리지 않습니다. 프로젝트별 계획은 `docs/PORTFOLIO_IMAGE_PLAN.md`.

## 6. PDF 만들기

Claude에게 "FITY PDF 만들어줘"라고 하면 됩니다. 직접 할 때(개발 PC, 처음 한 번 `npx playwright install chromium`):

```bash
npm run portfolio:export -- --slug fity --lang ko          # 한국어 A4 가로
npm run portfolio:export -- --slug fity --lang all --png   # 3개 언어 + 페이지별 PNG
npm run portfolio:export -- --slug fity --format 169       # 16:9 발표용
npm run portfolio:export -- --all                          # 출력 대상 전체
npm run portfolio:export -- --slug fity --mode external    # 외주 플랫폼 제출용(5–7쪽)
npm run portfolio:export -- --all --mode both --lang all   # 전체 × Full·External × 3개 언어
```

- 결과: `exports/<slug>/<slug>-<언어>-<형식>.pdf`(External은 끝에 `-external`), PNG는 같은 폴더의 `-pages/`. 실행 결과는 `exports/report.json`(쪽수·크기·잘림·외부 제출 준비 여부)
- External은 화면 이미지 대기(`file: null`)가 남아 있으면 미리보기는 되지만 **외부 제출 준비 미완료**로 표시됩니다.
- 웹 상세 페이지와 같은 데이터로 만들어지므로 웹을 고치면 PDF도 같이 바뀝니다.
- 쪽수는 화면·기능 수에 따라 자동으로 늘거나 줄어듭니다.
- 출력 중 글자·이미지가 페이지 밖으로 나가면 "잘림 의심"으로 알려 줍니다.
- 기본으로 `review` 상태까지 출력됩니다. 초안·비공개도 내부용으로 뽑으려면 `--stage all`.
- PDF 기능은 홈페이지 방문자에게 공개되지 않습니다(운영 사이트에서는 출력용 주소가 404).

## 7. 자료가 부족할 때

- **사진이 아직 없음** → 사진 자리에 "화면 준비 중" 틀이 표시됩니다(검토 단계에서만). 사진이 오면 파일만 넣으면 됩니다. 승인 전에 모두 채워야 합니다.
- **데모(아티팩트)는 있는데 스크린샷이 없음** → Claude가 데모를 직접 띄워 화면을 캡처합니다(모바일 1170×2532, PC 2880×1800). 데모 속 연락처처럼 실제 개인정보로 보일 수 있는 화면은 고릅니다.
- **관리자 화면을 공개할 수 없음** → 그 섹션(블록)을 지웁니다. 억지로 채우지 않습니다.
- **수행 범위가 불확실** → `pending`으로 두면 화면·PDF에는 나오지 않고, 확인 전에는 승인되지 않습니다.
- **상태·연도 모름** → 비워 두면 화면에서 자연스럽게 빠집니다.
- **번역이 없음** → 검토 단계에서는 한국어로 대체되어 보이고, 승인할 때 검사에서 막힙니다.
- **화면 속에 거래처 이름·로고가 있음** → 데모라면 캡처 때 `--mask <css>`로 가리고(글자는 `_clients.txt`에 있으면 자동으로 ○○○ 처리), 받은 이미지라면 가린 뒤 넣습니다. 가릴 수 없으면 그 화면을 뺍니다.
- **화면이 하나도 없음** → `images: []`, `thumbnail: []`로 두고 `stack`(기술 이름 배열)을 채우면, 카드와 표지가 기술 스택 타이포그래피로 표시되어 그대로 공개할 수 있습니다.

## 8. 검사 메시지 읽는 법

`npm run portfolio:check`
- `✖` 오류: 고치기 전에는 빌드가 되지 않습니다 (파일 없음, 중복 slug, 잘못된 블록, 외부 링크, 승인 상태인데 번역·사진 누락 등)
- `⚠` 경고: 빌드는 되지만 확인 권장 (사진 대기, 큰 파일, 낮은 해상도, 안 쓰는 사진 등)


## 상세 페이지 변형 (`theme.layout`)

상세 페이지가 모두 같은 모양으로 보이지 않도록 4가지 변형 중 하나를 고른다. 블록·원고는 그대로이고 배치와 틀만 바뀐다. 화면은 어느 변형에서도 잘리지 않는다. PDF는 변형과 관계없이 한 가지 레이아웃이다.

| 값 | 성격 | 표지 | 화면+글(textImage 좌우형) | 어울리는 프로젝트 |
|---|---|---|---|---|
| `split` (기본) | 클래식 | 왼쪽 글, 오른쪽 화면 | 좌우 교차 | 앱 위주, 실서비스 |
| `stage` | 중앙·시네마틱 | 가운데 정렬 제목, 아래 화면이 기울어진 무대에서 올라옴 | 위 글(가운데), 아래 큰 화면 | 비주얼이 강한 웹·브랜드 |
| `editorial` | 매거진 | 제목이 전체 폭, 아래 2단 문구, 화면은 오른쪽 | 큰 외곽선 숫자 + 좁은 글, 넓은 화면, 모서리 없는 띠 | 정보량 많은 업무·전문 도구 |
| `rail` | 프레임 | 화면이 강조색 패널 위에 놓임 | 화면은 색 패널 안, 글은 스크롤 중 고정 | 대시보드·운영 시스템 |

- 목록에서 이웃한 프로젝트끼리 같은 변형이 연달아 나오지 않게 고른다.
- 새 프로젝트 등록 시 성격에 맞춰 지정하고, 모르면 생략(split).

## 목록 순서와 첫 카드

- 목록은 카드(데스크톱 3열·태블릿 2열·모바일 1열)로 보인다. 각 탭의 첫 카드는 2칸 너비 대표 카드(업무 흐름 단계 표시), 마지막 줄이 비면 마지막 카드가 넓어진다. 카드 하나 = 테두리 패널 하나(이미지·번호·산업·이름·설명·요약·플랫폼/연도). 화면이 아직 없는 프로젝트는 업무 흐름 카드로 보인다. 제목이 "이름 — 설명" 형식이면 이름과 설명이 나뉘어 표시되고, 표지 eyebrow(예: DEMO · PoC)가 이미지 왼쪽 위 배지로 나온다.
- 각 탭의 첫 카드: '전체' 탭은 `featured: true`인 프로젝트, 나머지 탭은 다른 탭과 겹치지 않는 프로젝트가 자동으로 첫 카드가 된다(order가 앞선 것 우선). 나머지는 order 순.
- 프로젝트 수보다 탭이 많으면 한 탭은 겹칠 수 있다.

## 줄바꿈 규칙 (원고 작성 시 참고)

- 단어 중간에서 끊기지 않는다(한국어 어절·영어 단어·일본어 단어). 띄어쓰기 없는 아주 긴 문자열만 마지막 수단으로 끊긴다.
- "A·B"(공백 없는 가운뎃점)는 한 덩어리로 넘어간다. 줄바꿈을 허용하려면 "A · B"처럼 띄운다.
- 문장 끝의 짧은 단어(3자 이하, 영문 4자 이하)는 앞 단어와 함께 넘어간다.
