# 포트폴리오 등록 양식

아래 양식을 채워서 Claude 프로젝트 대화창에 보내면 바로 제작이 시작됩니다.
**필수는 두 가지뿐입니다: 프로젝트명, 자료 한 가지.** 나머지는 아는 것만 적고, 모르면 지우거나 비워 두세요.

```
[포트폴리오 등록]
프로젝트명:
자료: (하나 이상)
  - 스크린샷 첨부 / 데모·디자인 아티팩트 이름이나 링크 / GitHub 저장소 / 기획서·인수인계서 링크
설명: (몇 줄이면 충분 — 무엇을 하는 서비스인지, 누가 쓰는지, 주요 기능)

--- 아는 것만 ---
구분: 자체 서비스 / 고객사 프로젝트 (거래처 이름은 적어도 되지만 사이트에는 절대 나가지 않음)
공개: 공개 / 미리보기만 / 비공개
PIUS가 한 일: 기획 · UX · UI · 앱 · 웹 · 서버 · 관리자 · 인프라 · 운영
상태: 개발 중 / 출시 / 운영 중 / 구축 완료
연도:
분류: ERP·업무관리 / 플랫폼 / 모바일 앱 / 홈페이지·웹 / 커머스 / 시스템 연동
크게 보이기: 예 / 아니오
가릴 것: (화면에 나오면 안 되는 정보 — 금액, 내부 메뉴 등. 거래처 이름·로고는 따로 적지 않아도 항상 가림)
```

## 짧게 보내도 됩니다

```
[포트폴리오 등록]
프로젝트명: OOO 배차 ERP
자료: 첨부한 화면 8장
설명: 물류회사 내부 업무 통합. 배차, 직원 관리, 급여, 결재.
```

```
[포트폴리오 등록]
프로젝트명: PharmOS
자료: 아티팩트에 있는 PharmOS 디자인·기획서
```

## 보내면 Claude가 하는 일

1. 자료 찾기 — 첨부 파일, 이름이 같은 아티팩트(데모·디자인·기획서·인수인계서), 저장소까지 확인
2. 화면 확보 — 스크린샷이 없으면 데모를 직접 띄워 캡처 (모바일 1170×2532, PC 2880×1800)
3. 내용 정리 — 확인된 사실만으로 개요·서비스 구조·사용자 흐름·기능 문구 작성 (한·영·일)
4. 상세 페이지 구성 — 화면 종류와 수에 맞춰 정해진 블록 조합으로 배치
5. 홈페이지 반영 — 포트폴리오 목록·상세 페이지에 들어가고, 메인 Portfolio 섹션의 숫자(프로젝트·앱·웹·분야)가 자동으로 늘어남
6. PDF 출력 — A4 가로 한·영·일
7. 검사 — 타입·빌드·화면 확인, 미리보기 갱신, 작업 zip 전달
8. 마지막에 꼭 필요한 것만 질문 (예: 공개 승인, 확인 안 된 수행 범위)

## 꼭 알아 둘 점

- **확인되지 않은 숫자·사실은 넣지 않습니다.** 사용자 수, 매출, 성과 수치, 출시일은 자료에 근거가 있을 때만 씁니다.
- **화면을 지어내지 않습니다.** 받은 스크린샷이나 실제 데모 캡처만 씁니다.
- **공개 여부**
  - 기본은 바로 공개 승인(운영 사이트에 나옴). 고객사 프로젝트도 거래처 이름을 가린 채 바로 공개합니다
  - "비공개"라고 적으면 공개하지 않습니다
- **거래처는 공개 금지입니다.** 거래처 이름·로고·상호·서비스명은 제목·설명·화면 어디에도 나오지 않고, "여객 운송사"처럼 업종으로 바꿔 씁니다. 화면 속 이름과 로고도 가립니다.
- **화면이 없어도 등록됩니다.** 글과 기술 스택만으로 카드·상세 페이지가 만들어지고, 화면은 나중에 추가하면 됩니다.
- 외부 링크(서비스 주소·GitHub·Figma·QR)는 포트폴리오에 넣지 않습니다.
- 실제 고객 개인정보·운영 데이터가 보이는 화면은 쓰지 않습니다. 데모의 가짜 연락처처럼 실제처럼 보이는 화면도 고릅니다.
- 수정은 "OOO 포트폴리오에서 ~ 바꿔줘", 내리기는 "OOO 내려줘", 순서는 "OOO를 맨 앞으로"처럼 말하면 됩니다.
